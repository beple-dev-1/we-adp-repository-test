### 확인한 요구사항 요약

적용 대상이 에이블리이므로 대상 화면은 에이블리 전용 회원가입 웹뷰 EXW-UWV-70-30-10-C(원본 zero_webview_join_aby_v1_view.jsp)이고, 공통 회원가입 화면(EXW-UWV-10-S)은 이번 범위에서 제외했다. 현재 HTML을 확인한 결과 이 화면은 본인정보 입력 → 약관 동의 → 인증번호 → 가입완료 4단계이며 본인정보 단계의 입력 칸은 휴대폰번호·이름·생년월일(에이블리 전달값으로 프리필·잠금), 주민등록번호 뒷자리, 통신사, 이메일(선택, js-step-5)뿐이라 자유 입력 메모 칸이 없어 새로 만들어야 한다. 공통 스크립트가 js-require가 붙은 칸이 모두 채워져야 「인증하기」 잠금을 푸는 구조이므로, 선택 항목인 메모는 이메일 칸과 동일하게 js-require 없이 넣어 비워도 가입이 진행되게 한다. 입력값은 회원 정보에 함께 저장해 백오피스 회원 상세에서 조회하기로 했는데, 백오피스 계열 화면(BPG·HIT·MCH 등)은 아직 화면명·메뉴 경로가 추출되지 않아 해당 회원 상세 화면을 색인에서 특정할 수 없어 별도 항목으로 분리했다.

## 5. 완료 조건

- 에이블리 회원가입 웹뷰 본인정보 입력 단계에서 이메일 칸 다음에 「메모(선택)」 한 줄 입력 칸이 보인다.
- 메모를 비워 둔 상태에서도 주민등록번호 뒷자리와 통신사를 채우면 「인증하기」 버튼이 활성화되고 가입이 끝까지 진행된다.
- 메모 칸에는 최대 100자까지 입력되고, 그 이상은 화면과 서버 모두에서 저장되지 않는다.
- 메모를 입력해 가입을 완료하면 입력값이 해당 회원 정보에 저장된다.
- 백오피스 회원 상세에서 가입 시 입력된 메모를 읽기 전용으로 확인할 수 있고, 미입력 회원은 빈 값으로 표시된다.

## 7. 화면 외 구현

### 데이터

- **회원 정보 테이블(TB_MEMBER 계열)** — 가입자 메모를 담을 컬럼을 추가한다. 길이는 화면 입력 상한 100자를 수용하는 크기로 잡고, 미입력 시 NULL을 허용한다.
  - 근거: 인터뷰에서 「회원 정보에 함께 저장」으로 확정. 이메일도 TB_MEMBER.EMAIL 컬럼에 저장한다는 근거가 EXW-UWV-70-30-10-C.html 주석에 있다.
  - 판정 방법: 에이블리 회원가입에서 메모를 입력해 가입하면 해당 회원 행의 메모 컬럼에 입력값이 저장되고, 비워 두면 NULL로 저장된다.

### API

- **에이블리 회원가입 확정 처리(zero_webview_join_aby 가입 확정 전문)** — 가입 확정 요청에 메모 항목을 추가로 받아 회원 정보와 함께 저장한다. 선택 항목이므로 값이 없어도 가입이 정상 처리돼야 하고, 100자 초과 입력은 서버에서도 거절한다.
  - 근거: 메모는 선택 입력이라 비워도 가입 가능하도록 인터뷰에서 확정했고, 화면의 maxlength만으로는 서버 검증이 보장되지 않는다.
  - 판정 방법: 메모 미입력·정상 입력·100자 초과 입력 세 경우로 가입 API를 호출해 각각 정상 가입·정상 저장·검증 오류가 반환된다.
- **백오피스 회원 상세 조회** — 회원 상세 조회 응답에 가입 시 입력된 메모를 포함해 운영자가 읽기 전용으로 확인할 수 있게 한다.
  - 근거: 인터뷰에서 「백오피스 회원 상세에서 조회할 수 있게 한다」로 확정.
  - 판정 방법: 메모를 입력해 가입한 회원을 백오피스 회원 상세에서 조회하면 입력한 메모가 그대로 보이고, 미입력 회원은 빈 값으로 보인다.

### 권한

- **백오피스 회원 상세 조회 권한** — 기존 회원 상세 조회 권한을 그대로 쓰고 별도 권한을 신설하지 않는다. 메모는 조회만 가능하고 백오피스에서 수정하지 않는다.
  - 근거: 인터뷰에서 메모 입력 주체는 가입자로 한정했고, 운영자 편집 요구는 나오지 않았다.
  - 판정 방법: 회원 상세 조회 권한이 있는 계정에서만 메모가 보이고, 백오피스에는 메모 수정 수단이 없다.
