# DR-015 · 돌려받을 것

개발이 끝나면 아래 **「돌려보내는 법」대로** 돌려보내 주십시오. 이 문서는 무엇을 돌려받을지
알리는 안내서이고, 빌더가 읽는 것은 그 절에 적힌 파일들입니다.

| | |
|---|---|
| 돌려보낼 브랜치 | `feedback/EXW/DR-015` |
| 갈라 올 기준 커밋 | `cc0c45dab08ea18c73d023bd0307b1ba9052a5c0` |

⛔ **기준 커밋에서 갈라 주십시오.** 그 뒤 기본 브랜치가 바뀌어도 괜찮습니다 — 며칠 걸려도 됩니다.
다만 **이 요청의 화면 파일(html·화면 md)을 그 사이 기본 브랜치에서 누가 고쳤으면** — `unchanged` 로
적은 것도 — 그대로 받으면 덮이거나 한 화면에 옛것과 새것이 섞이므로 **배치를 통째로 거절**합니다.
색인(`index.json`)은 `changed` 로 보낼 때만 따집니다. 거절되면 지금 기본 브랜치의 그 파일을 보고
합쳐서, 회신서의 `base` 를 지금 기본 브랜치의 머리로 고쳐 다시 보내 주십시오 — 전체를 다시 만들
필요는 없습니다.

⛔ **전달 브랜치 위에 얹지 마십시오.** 거기에는 기획이 그린 화면(to-be)이 들어 있어
그 위에서 갈라 오면 그것이 **사실인 척** 섞여 들어옵니다.

## 돌려보내는 법

⛔ 빌더는 **이 문서를 읽지 않습니다.** 아래 표의 자리에 놓인 파일만 읽습니다.

1. 기획 저장소 기본 브랜치의 기준 커밋 `cc0c45dab08ea18c73d023bd0307b1ba9052a5c0` 에서 `feedback/EXW/DR-015` 브랜치를 땁니다.
2. 아래 표의 자리에 파일을 놓고 그 브랜치에 커밋합니다.
3. 그 브랜치를 기획 저장소에 올리고 기획에 알려 주십시오. 기획이 「개발 결과 받기」를 누르면
   빌더가 판정해 받습니다. 거절되면 사유가 기획 화면에 뜹니다.

| 무엇 | 자리 | 언제 |
|---|---|---|
| `EXW-UWV-70-30-10-C` 화면(html) | `core/EXW/pages/EXW-UWV-70-30-10-C.html` | 회신서에 `pages` 를 `changed` 로 적었을 때만 |
| `EXW-UWV-70-30-10-C` 화면 md | `core/EXW/pages/EXW-UWV-70-30-10-C.md` | 회신서에 `screen-md` 를 `changed` 로 적었을 때만 |
| `EXW-UWV-70-30-10-C` 색인 | `index.json` | 회신서에 `index` 를 `changed` 로 적었을 때만 |
| 회신서 | `DR-015/return.json` | 늘 — 없으면 통째로 거절합니다 |
| 단위테스트 결과 | `DR-015/return/unit-tests.md` | 3절 표를 채워서 |
| 통합테스트 결과 | `DR-015/return/integration-tests.md` | 4절 표를 채워서 |

⚠ 회신서와 테스트 결과는 기본 브랜치에 들어가지 않습니다 — 빌더가 읽어 판정하고, 테스트 결과는
빌더에 담습니다. 테스트 결과 표는 **앞의 칸을 고치지 말고** 실제 결과·판정·근거만 채워 주십시오.

회신서 견본입니다. `changed 또는 unchanged` 를 칸마다 **하나로 바꿔** 주십시오 —
그대로 두면 모르는 값으로 거절합니다. 뜻은 1절에 있습니다.

```json
{
  "dr" : "DR-015",
  "base" : "cc0c45dab08ea18c73d023bd0307b1ba9052a5c0",
  "screens" : [
    {
      "screenId" : "EXW-UWV-70-30-10-C",
      "pages" : "changed 또는 unchanged",
      "screen-md" : "changed 또는 unchanged",
      "index" : "changed 또는 unchanged"
    }
  ]
}
```

## 1. 화면 — 실제로 만든 것을 돌려주십시오

필수 구성요소마다 `changed` 또는 `unchanged` 를 **정확히 하나** 적어 주십시오.
⚠ `unchanged` 는 「보았고 바꿀 것이 없었다」는 뜻입니다 — 안 본 것과 다릅니다.

| 화면ID | 시스템 | 필수 구성요소 |
|---|---|---|
| `EXW-UWV-70-30-10-C` | EXW | `pages` · `screen-md` · `index` |

값(`changed`·`unchanged`)은 **회신서에만** 적습니다 — 이 표에 적어도 빌더는 읽지 않습니다.
- `pages` — 화면 html 을 고쳤으면 `changed`
- `screen-md` — 기능정의서를 고쳤으면 `changed`
- `index` — 화면 이름·종류·메뉴 위치가 바뀌었으면 `changed` (`index.json` 의 그 화면 줄)

⛔ **`ia.md`(메뉴구조도)는 받지 않습니다.**

## 2. 화면 외 구현 — 무엇을 어떻게 했는지 적어 주십시오

| 대상 | 요청한 변경 |
|---|---|
| `회원 정보 테이블(TB_MEMBER 계열)` | 가입자 메모를 담을 컬럼을 추가한다. 길이는 화면 입력 상한 100자를 수용하는 크기로 잡고, 미입력 시 NULL을 허용한다. |
| `에이블리 회원가입 확정 처리(zero_webview_join_aby 가입 확정 전문)` | 가입 확정 요청에 메모 항목을 추가로 받아 회원 정보와 함께 저장한다. 선택 항목이므로 값이 없어도 가입이 정상 처리돼야 하고, 100자 초과 입력은 서버에서도 거절한다. |
| `백오피스 회원 상세 조회` | 회원 상세 조회 응답에 가입 시 입력된 메모를 포함해 운영자가 읽기 전용으로 확인할 수 있게 한다. |
| `백오피스 회원 상세 조회 권한` | 기존 회원 상세 조회 권한을 그대로 쓰고 별도 권한을 신설하지 않는다. 메모는 조회만 가능하고 백오피스에서 수정하지 않는다. |

구현한 결과는 **3절 단위테스트** 표에 채워 돌려주십시오 — 단위테스트가 이 항목마다 하나씩 붙어 있습니다.

⚠ 도메인 문서(`domains/…`)는 지금 돌려받는 자리가 없어 **보내셔도 반영되지 않습니다.**
고친 내용은 단위테스트의 근거 칸에 적어 주십시오.
